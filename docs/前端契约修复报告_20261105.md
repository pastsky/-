## 2. 修复清单

### 2.1 统一请求层（`src/utils/request.js`）

- 单一 axios 实例，`baseURL` 取 `VITE_API_BASE_URL`，请求头注入 `Authorization: Bearer <token>`。
- 业务码与 HTTP 双判：
  - `code=0` → 返回 `data`；
  - `2000/2002`（及 HTTP 401）→ 清 token 跳登录；
  - `2001` → 仅提示（密码错误不跳登录）；
  - `1002` / HTTP 403 → 提示无权限，不跳转；
  - `1001/3001/4000` / HTTP 404 → 提示资源不存在；
  - `3000/3002` / HTTP 409 → 直接展示后端 `message`；
  - `1000` / HTTP 400 → 展示参数错误 `message`。
- 文件流返回 `{ blob, filename }`，文件名按 `Content-Disposition`（含 RFC5987 `filename*`）解析；blob 形态的错误响应会先解析 JSON 再提示。

### 2.2 列表三形态解包器（`src/utils/unwrap.js`）

| 形态 | 解包器 | 已接入接口 |
|---|---|---|
| 分页 `{list,total,page,pageSize}` | `unwrapPage` | work-orders、pool、elevators、maintenance plans/tasks、inspection plans/tasks、notifications、users、feedback、certificates、audit-logs、cs-workbench/overdue、exports |
| 仅 `{list}` | `unwrapList` | teams、teams/{id}/members、branches、duty-schedules、repairer-tags、type-cert-mappings、inspection/point-templates、certificates/mine |
| 裸数组 `[...]` | `unwrapArray` | users/engineers、work-orders/{id}/logs、stats/type-distribution、stats/engineer-performance |

- v1.3 的 4 个 `{list}` 接口（BOP68/72/84/96）与 BOP82 `certificates/mine` 已按 `data.list` 读取，修复了“对象当数组遍历”的隐患。
- 字典类（branches / teams / repairer-tags / type-cert-mappings / point-templates）接入 `cachedRequest` 缓存 + 并发去重，写操作后主动失效缓存。

### 2.7 图片上传（2026-11-05 追加）

根因（见《工单故障图片不显示_定责与修复》）：
1. `handleUpload` 为 async 且内部调用 `options.onSuccess(res)`，el-upload 还会把 async 返回值再 `then(onSuccess)` 一次，第二次为 `undefined`，覆盖了 `file.response`；
2. 提交时取 `file.url`（`blob:` 预览地址）而非 `file.response.url`，blob 地址被写入 `work_order.images`；
3. `compressImage` 重编码为 JPEG 但保留 `.png` 扩展名，后端三重校验（扩展名/MIME/魔数）必然 400。

修复：
- 三处 `handleUpload`（报修、工单完工、维保完工）改为直接 `return uploadImage(compressed)`，由 el-upload 写入 `file.response`；
- 新增 `src/utils/upload.js`：`collectUploadedUrls` 优先取 `response.url`、过滤 `blob:`，`hasPendingUpload` 拦截未完成/失败图片；
- 四处提交（报修 `images`、完工 `images`、内部备注 `images`、兜底改单 `finishImages`）统一改用解包工具；
- `compressImage` 输出文件名扩展名同步改为 `.jpg`；
- 工单详情的 3 处 `el-image` 增加 `#error` 占位「图片失效」，避免破图无提示。

验证：E2E 新增断言——报修创建与完工提交的请求体 `images[0]` 必须为 `http(s)://` 服务端地址；详情坏图展示占位。

## 4. 遗留与风险

1. **真实后端未启动**：8080/8082 均不可达，登录、真实业务码（3002/4002）、上传、导出下载需启动后端后按 §5 复测。
2. **经理端部分页面角色入口仍偏保守**：班组、维保计划、巡检计划页仅 ADMIN/CS 入口；契约允许 ENG/BA/VA 只读部分数据，入口收敛不影响后端 403 边界。
3. **维保计划字段**：仍使用存量 `cycleType`，v1.1 仅声明“追加 frequency/frequencyTime/pointTemplateId”，未提供 v1.0 字段清单，暂不改动存量字段，待后端确认后再补。
