# 前端对接结果与剩余差异（对齐后端契约 v1.2）

> 基线：`PR-006-contract-baseline.md`（v1.0）→ `PR-012-022-contract-baseline.md`（v1.1）→ `contract-v1.2-changelog.md`（v1.2，冲突时以此为准）
> 本文记录**前端已完成的对齐**与**尚未落地的差异**，后端无需按旧版本文档再改接口。

## 一、已按后端实现完成对齐（无需后端改动）

### 1. 抢单出口改为 `PROCESSING`

之前前端曾按生命周期归档实现为 `PENDING → ASSIGNED`，现已改为与后端一致：

- `POST /api/work-orders/{id}/grab` → `PENDING + pool_flag=1 → PROCESSING`，写 `assign_time`、`accept_time`；
- 失败码按 `1002`（无权限/收工）、`3000`（已被抢/在途/预约冲突）、`3001`（不存在）提示；
- 「接单」按钮只在 `ASSIGNED`（派单路径）出现，抢单路径不再需要接单。

### 2. 退回与入池拆成两条接口

- `POST /api/work-orders/{id}/return`：维修工退回，body `{remark}`（可空），回 `PENDING`、清 assignee、`pool_flag` 不变；
- `POST /api/work-orders/{id}/to-pool`：客服入池，body `{reason}`（必填）；
- 前端「退回」弹窗只填说明；「推送入池」单独按钮，二者不再共用 target 字段。

### 3. 转交

`POST /api/work-orders/{id}/transfer`：body `{targetAssigneeId, reason}`，`ASSIGNED/PROCESSING → ASSIGNED`，清 `accept_time`；前端已改用 `targetAssigneeId`，转交后提示「待对方接单」。

### 4. 内部备注 / 兜底改单

- `POST /api/work-orders/{id}/internal-notes`：body `{remark, images}`，两者至少一项、图片 ≤3；
- `POST /api/work-orders/{id}/force-status`：仅 `PROCESSING→ASSIGNED`、`PROCESSING→COMPLETED`、`PENDING→CANCELED`，原因必填；补录完工要求至少 1 张照片。

### 5. 批量操作

`batch-assign` / `batch-to-pool` / `batch-cancel` 三条路径，body `{orderIds, reason, assigneeId?}`，前端按 `{successCount, failureCount, failures[]}` 展示部分成功。

### 6. 维修日历

`GET /api/engineers/{engineerId}/calendar?startDate&endDate&types=WORK_ORDER,MAINT_TASK,INSPECTION,DUTY`，按 `blocks[].startTime/endTime` 渲染；管理端可切维修工。

### 7. 客服工作台

`GET /api/cs-workbench/todos`（9 项计数）+ `GET /api/cs-workbench/overdue?type=&page=&pageSize=`（`overdueHours` 倒序）。

### 8. 导出中心

`POST /api/exports`（`reportType`+`format` 矩阵校验）→ `GET /api/exports` 轮询 `QUEUED/RUNNING/SUCCESS` → `GET /api/exports/{id}/download`（blob，`responseType: 'blob'` 已在 axios 拦截器放行）；`GET /api/stats/team-performance` 展示班组统计。

### 9. 新增页面使用的接口

- 电梯台账：`/api/elevators` CRUD、`/import`、`/{id}/inspect`、`/{id}/profile?tab=`；
- 班组与审计：`/api/teams` CRUD、`/{id}/members`（全量覆盖）、`/api/audit-logs`；
- 反馈：`/api/feedback`、`/{id}`、`PUT /{id}/resolve`（`resolveRemark` 必填）。

## 三、联调自测要点

1. 派单 → 接单 → 完工（不传图应 `1000`）→ 待回访 → 回访归档；
2. 池单抢单后状态直接为「处理中」，有在途单的维修工抢单返回 `3000`；
3. 退回后再「推送入池」，工单出现在池中；
4. 转交后原处理人失去操作权限，新处理人状态为「待接单」；
5. 批量入池/取消返回 `successCount/failureCount`，失败行有 `code/message`；
6. 导出任务创建后轮询到 `SUCCESS` 才能下载，过期任务 `downloadable=false`；
7. 电梯超期年检在列表红标，删除有关联工单的电梯返回 `3002`；
8. 班组删除有成员时返回 `3002`，审计日志记录成员变更。
